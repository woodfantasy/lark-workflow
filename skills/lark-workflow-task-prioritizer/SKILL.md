# 智能任务优先级排序工作流

**CRITICAL — 开始前 MUST 先用 Read 工具读取 [`lark-shared/SKILL.md`](https://github.com/larksuite/cli/blob/main/skills/lark-shared/SKILL.md)，其中包含认证、权限处理和安全规则。**

## 适用场景

- "帮我排一下任务优先级" / "今天应该先做什么"
- "任务太多了，帮我理一下" / "哪些事情最紧急"
- "安排一下今天的工作" / "帮我做个工作计划"
- "Task prioritization" / "优先级排序"
- "时间不够了，哪些可以推迟" / "今天必须完成的是哪些"

## 核心价值

不只是列出任务清单，而是**结合日程约束和紧急/重要维度**进行智能排序，并给出具体的**时间块建议**（什么时候做什么）。

## 前置条件

仅支持 **user 身份**。执行前确保已授权：

```bash
lark-cli auth login --domain task,calendar
```

## 工作流

```
 task +get-my-tasks ──► 所有未完成任务
                              │
 calendar +agenda   ──► 今日日程（时间约束）
                              │
                              ▼
                     AI 分析（紧急/重要矩阵）
                              │
                 ┌────────────┼────────────┐
                 ▼            ▼            ▼
           🔴 紧急重要    🟡 重要不紧急   🟢 紧急不重要
           (立刻做)      (安排时间做)    (委托或快速处理)
                              │
                              ▼
                    时间块分配（匹配空闲时段）
                              │
                              ▼
                      优先级排序 + 行动建议
```

### Step 1: 确定目标时间范围

默认**今天**。推断规则：
- "今天的任务" / "今天先做什么" → 今天
- "这周的优先级" / "本周计划" → 本周（周一~周日）
- "明天的安排" → 明天

```bash
# 获取目标日期范围
date "+%Y-%m-%dT00:00:00%z"
date "+%Y-%m-%dT23:59:59%z"
```

### Step 2: 获取未完成任务

参考 [`lark-task/SKILL.md`](https://github.com/larksuite/cli/blob/main/skills/lark-task/SKILL.md)。

```bash
# 获取所有未完成任务
lark-cli task +get-my-tasks --format json

# 如果只看近期任务，加截止日期过滤
lark-cli task +get-my-tasks --due-end "<end_date>" --format json
```

从返回结果中提取每个任务的：
- `summary`：任务标题
- `due`：截止时间
- `created_at`：创建时间
- `updated_at`：最后更新时间
- `creator`：创建者（判断是自己创建 vs 他人分配）

### Step 3: 获取日程约束

参考 [`lark-calendar/SKILL.md`](https://github.com/larksuite/cli/blob/main/skills/lark-calendar/SKILL.md)。

```bash
# 获取目标日期的日程
lark-cli calendar +agenda --start "<start>" --end "<end>"
```

从日程中提取：
- 已被占用的时间段
- 空闲时段（用于分配任务时间块）

### Step 4: AI 分析与排序

**紧急/重要矩阵评估规则：**

| 维度 | 信号 |
|------|------|
| **紧急** | 截止日期在今天/明天；已过期；创建者是上级/客户 |
| **重要** | 任务标题关键词（"汇报"、"决策"、"上线"、"交付"）；关联会议在今天；影响他人进度 |
| **不紧急** | 截止日期在 3 天后；无截止日期且非他人分配 |
| **不重要** | 任务标题关键词（"了解"、"调研"、"可选"）；无截止日期无关联 |

**分类规则：**

```
🔴 P0 — 紧急且重要（Do First）
  · 今天到期 or 已过期
  · 关键交付物 or 影响他人进度

🟡 P1 — 重要不紧急（Schedule）
  · 截止日期在 2-7 天内
  · 需要深度思考或较长时间

🟢 P2 — 紧急不重要（Delegate/Quick Do）
  · 今天到期但预计 <30 分钟可完成
  · 简单回复、确认类任务

⚪ P3 — 不紧急不重要（Backlog）
  · 无截止日期 or 截止日期 >7 天
  · 非核心低优先级
```

### Step 5: 时间块分配

基于 Step 3 的空闲时段和 Step 4 的排序，生成时间块建议：

```
空闲时段推算：
  全天工作时间（09:00-18:00）- 已有日程 = 可用时间块

分配策略：
  1. P0 任务优先分配到最早的空闲时段
  2. P1 任务分配到较长的连续空闲时段（>1小时）
  3. P2 任务分配到碎片时间（会议间隙 30 分钟内）
  4. P3 任务不分配时间，放入 Backlog
```

### Step 6: 生成排序结果

```markdown
## 📋 任务优先级排序（{YYYY-MM-DD 星期X}）

### 📊 概览
- 📌 共 **N** 项未完成任务
- 🔴 **A** 项紧急重要 | 🟡 **B** 项重要 | 🟢 **C** 项快速处理 | ⚪ **D** 项 Backlog
- ⏰ 今日可用工作时间：**X 小时**（扣除 Y 场会议）

### 🔴 P0 — 立刻做（紧急且重要）

| # | 任务 | 截止 | 建议时间段 | 理由 |
|---|------|------|-----------|------|
| 1 | 提交 Q2 预算报告 | 今天 18:00 | 09:00-10:30 | 今日截止，需 1.5h |
| 2 | 回复客户技术方案 | 已过期 | 10:30-11:30 | 已过期，影响客户进度 |

### 🟡 P1 — 安排时间做（重要不紧急）

| # | 任务 | 截止 | 建议时间段 | 理由 |
|---|------|------|-----------|------|
| 3 | 撰写技术设计文档 | 周五 | 14:00-16:00 | 需要深度思考，安排午后 |
| 4 | 准备周一评审材料 | 下周一 | 明天处理 | 时间充裕，今天优先 P0 |

### 🟢 P2 — 快速处理（<30min）

| # | 任务 | 预估时间 | 建议时间段 |
|---|------|---------|-----------|
| 5 | 确认会议纪要 | 10min | 11:30-11:40（会前间隙） |
| 6 | 审阅 PR | 20min | 16:00-16:20 |

### ⚪ P3 — Backlog（可推迟）
- 调研竞品 XX 功能（无截止日期）
- 整理个人笔记（非紧急）

### ⏰ 今日时间规划

```
09:00 ███████ 提交 Q2 预算报告（P0）
10:30 ███████ 回复客户技术方案（P0）
11:30 ██ 确认会议纪要（P2）
12:00 ░░░░░░ 午休
13:00 ████ 产品需求评审（📅 会议）
14:00 █████████ 撰写技术设计文档（P1）
16:00 ███ 审阅 PR（P2）
16:30 ████ 技术方案讨论（📅 会议）
17:30 ░░░░ 缓冲时间
```

### 💡 建议
- {如果 P0 任务过多} "今天 P0 任务较多，建议与{上级/相关人}沟通是否可以延期 XX"
- {如果有冲突} "任务 X 和日程 Y 时间冲突，建议..."
- {如果任务乐观估计时间 > 可用时间} "今日可用时间不足以完成所有 P0 任务，建议优先处理第 1、2 项"
```

## 权限表

| 步骤 | 命令 | 所需 scope | 是否必选 |
|------|------|-----------|---------|
| 获取任务 | `task +get-my-tasks` | `task:task:read` | ✅ 必选 |
| 获取日程 | `calendar +agenda` | `calendar:calendar.event:read` | ✅ 必选 |
