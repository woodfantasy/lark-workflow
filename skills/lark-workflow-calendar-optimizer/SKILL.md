# 日程优化助手工作流

**CRITICAL — 开始前 MUST 先用 Read 工具读取 [`lark-shared/SKILL.md`](https://github.com/larksuite/cli/blob/main/skills/lark-shared/SKILL.md)，其中包含认证、权限处理和安全规则。**

## 适用场景

- "帮我优化明天的日程" / "处理日程冲突"
- "看看我的日程有什么问题" / "日程安排合理吗"
- "哪些会议可以推掉" / "日程太满了怎么优化"
- "帮我整理一下这周的日程" / "Calendar optimizer"
- "明天有日程冲突" / "帮我重新排一下日程"

与已有 `smart-scheduler`（约新会议：找空闲时段→创建日程）互补，本 Skill 面向**现有日程的诊断和优化**：检测问题→分析原因→建议方案。形成「日程双子套件」。

## 前置条件

支持 **user 身份**。执行前确保已授权：

```bash
lark-cli auth login --domain calendar
```

## 工作流

```
指定分析范围 ──► calendar +agenda（获取全部日程）
                       │
                       ▼
                  日程分析引擎
              ┌────────┼────────┐
              ▼        ▼        ▼
          冲突检测  碎片分析  效率评估
                       │
                       ▼
              诊断报告 + 优化方案
                       │
                       ▼（用户确认）
              calendar events patch / events delete（可选执行）
```

### Step 1: 获取日程数据

参考 [`lark-calendar/SKILL.md`](https://github.com/larksuite/cli/blob/main/skills/lark-calendar/SKILL.md)。

```bash
# 获取目标日期的日程
lark-cli calendar +agenda --start "<start>" --end "<end>"
```

> **注意**：日期使用 `date` 命令计算。

```bash
# 获取明天
date -v+1d "+%Y-%m-%dT00:00:00%z"
date -v+1d "+%Y-%m-%dT23:59:59%z"

# 获取本周
date -v-monday "+%Y-%m-%dT00:00:00%z"
date -v+friday "+%Y-%m-%dT23:59:59%z"
```

### Step 2: 日程分析引擎

**2.1 冲突检测：**

遍历日程列表（按开始时间排序），检查相邻事件：

```
冲突类型：
A. 完全重叠：事件 B 完全在事件 A 的时间范围内
B. 部分重叠：事件 B 的开始时间 < 事件 A 的结束时间
C. 首尾相连（无缓冲）：事件 B 开始时间 == 事件 A 结束时间
```

对于已拒绝（`decline`）的日程：标记为不占用时间，不参与冲突检测。

**2.2 碎片时间分析：**

```
碎片 = 两个会议之间的空闲段

碎片分类：
- 微碎片（< 15分钟）：几乎无法利用
- 小碎片（15-30分钟）：只能做简单任务
- 有效空闲（30-60分钟）：可以处理中等任务
- 专注时段（> 60分钟）：适合深度工作
```

**2.3 效率评估：**

| 指标 | 计算方式 | 健康阈值 |
|------|---------|---------|
| 会议占比 | 会议总时长 / 工作时间 | < 40% |
| 最长连续会议 | 连续无间断的会议总时长 | < 2 小时 |
| 专注时段数 | > 1 小时连续空闲的段数 | ≥ 2 段 |
| 午休保护 | 12:00-13:00 是否有会议 | 无会议 |
| 缓冲时间 | 相邻会议间 ≥ 15 分钟的比例 | > 70% |

### Step 3: 生成诊断报告

```markdown
## 🗓️ 日程诊断报告（{日期}）

### 整体评估
- **日程总数**：{N} 场
- **会议总时长**：{X} 小时（占工作时间 {P}%）
- **健康度**：{🟢 健康 / 🟡 偏满 / 🔴 过载}

### ⚠️ 发现的问题

#### 🔴 时间冲突（{N} 处）
| # | 冲突事件 | 时间 | 类型 |
|---|---------|------|------|
| 1 | 「产品评审」 vs 「技术方案讨论」 | 14:00-15:00 | 部分重叠 |
| 2 | 「1v1」 vs 「团队周会」 | 16:00-17:00 | 完全重叠 |

#### 🟡 碎片时间（{N} 段微碎片）
| # | 时间段 | 时长 | 前后会议 |
|---|--------|------|---------|
| 1 | 10:00-10:10 | 10min | 需求评审 → 技术讨论 |
| 2 | 15:00-15:15 | 15min | 客户会议 → 1v1 |

#### 🟡 连续会议（无缓冲）
- ⚠️ 09:00-12:00 连续 3 小时会议，无休息时间
- ⚠️ 14:00-16:30 连续 2.5 小时

#### 🟡 效率指标
| 指标 | 当前值 | 健康阈值 | 状态 |
|------|--------|---------|------|
| 会议占比 | 65% | < 40% | 🔴 |
| 专注时段 | 0 段 | ≥ 2 段 | 🔴 |
| 午休保护 | 有 1 场会议 | 无会议 | 🟡 |
| 缓冲时间率 | 30% | > 70% | 🔴 |

### 📅 时间线可视化

```
09:00 ████ 产品需求评审
10:00 ████ 技术方案讨论
11:00 ████ 团队周会
12:00 ████ 客户午餐会 ⚠️ 占用午休
13:00 ░░░░ 空闲
14:00 ████ 产品评审 ← 冲突
14:00 ████ 技术方案讨论 ← 冲突
15:00 ░░ 微碎片(15min)
15:15 ████ 1v1
16:00 ████ 1v1 ← 冲突
16:00 ████ 团队周会 ← 冲突
17:00 ░░░░ 空闲
```

### 💡 优化方案

#### 方案 A：冲突解决
1. **「技术方案讨论」（14:00）** → 建议改到 **明天 10:00**（当日已无可用时段）
2. **「团队周会」（16:00）** → 建议改到 **13:30-14:00**（填充午后空闲）

#### 方案 B：增加缓冲
1. **「团队周会」（11:00）** → 缩短为 45 分钟（11:00-11:45），释放 15 分钟缓冲
2. **「客户午餐会」（12:00）** → 如非必须，建议移至 13:00

#### 方案 C：释放深度工作时间
1. 将 **「1v1」（15:15）** 移至下午最后（17:00），释放 15:00-17:00 为专注时段

选择一个方案（输入 A/B/C），或调整后确认执行。
```

### Step 4: 执行优化（可选，用户确认后）

> **⚠️ 安全规则：必须用户确认后才修改日程。**

```bash
# 修改日程时间
lark-cli calendar events patch --event "<event_id>" \
  --start "<新开始时间>" --end "<新结束时间>"

# 或取消日程（如果用户决定推掉某个会议）
lark-cli calendar events delete --event "<event_id>"
```

> **注意**：修改他人发起的日程可能无权限。如果是他人组织的会议，建议改为"拒绝"而非修改时间。

```bash
# 拒绝日程
lark-cli calendar +rsvp --event "<event_id>" --rsvp "decline"
```

## 容错机制

| 异常场景 | 处理方式 |
|---------|---------|
| 目标日期无日程 | 提示"该日期暂无日程"，建议选择其他日期 |
| calendar 命令报权限或身份错误 | v1.0.5 起 calendar 不再自动回退到 bot 身份，需显式 user 登录。提示用户执行 `lark-cli auth login --domain calendar` |
| 无法修改他人日程 | 建议拒绝或联系组织者协调 |
| 全天事件 | 标记但不参与冲突计算（除非用户指定） |
| 已拒绝的日程 | 标记为"已拒绝"，不参与冲突和时间计算 |

## 权限表

| 步骤 | 命令 | 所需 scope | 是否必选 |
|------|------|-----------|---------|
| 获取日程 | `calendar +agenda` | `calendar:calendar.event:read` | ✅ 必选 |
| 修改日程 | `calendar events patch` | `calendar:calendar.event:write` | 可选（执行优化时） |
| 拒绝日程 | `calendar +rsvp` | `calendar:calendar.event:write` | 可选 |
| 删除日程 | `calendar events delete` | `calendar:calendar.event:write` | 可选 |
